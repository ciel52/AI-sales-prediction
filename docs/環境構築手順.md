# 環境構築手順書（来店・売上予測デスク）

動作確認済みの目安: **Python 3.12** / **Node.js 22** / macOS。Windows でも同じ流れです（起動コマンドだけ末尾を参照）。

---

## 1. 完成イメージ

2つのプロセスを同時に動かします。


| 役割  | アドレス                                           | 中身                 |
| --- | ---------------------------------------------- | ------------------ |
| API | [http://127.0.0.1:8000](http://127.0.0.1:8000) | 学習・予測・データ取込・施策チャット |
| Web | [http://127.0.0.1:3000](http://127.0.0.1:3000) | 予測デスク画面            |


ブラウザで開くのは **[http://127.0.0.1:3000](http://127.0.0.1:3000)** です。画面上部に「予測デスク」「予測のしくみ」があります。

学習データがあれば店舗を選んで日次／週次／月次の予測ができます。LLM の API キーが無くても、数値予測とルールベースの施策文は動きます。

## 3. 配布物



### 3.1 ソースコード

少なくとも次が入っていること。

```
api/          FastAPI
web/          Next.js
src/          予測・ETL・施策提案
requirements.txt
.env.example
```

検証用の `archive/` は環境構築には不要です。あっても害はありません。

### 3.2 学習データ（どちらか一方）

`data/*.csv` と `test_data/` は Git に入れていません（実データのため）。次の **A または B** を用意します。

**A. 店舗×日の集計表（推奨・すぐ起動できる）**

`data/real_store_daily.csv` をプロジェクトの `data/` に置く。

必要な列の例: `shop_id`, `date`, `receipts`, `net_sales`, `avg_spend` など。既存の検証用ファイルは約 640KB です。

**B. 生の購買履歴（サーバで自動変換）**

必要なファイルは次の1つです。

- `buying_history.csv`（CSPM 購買履歴。TSV でも可）

配置場所は次のどれでも構いません。API 起動時に自動で店舗×日へ変換します。

1. `test_data/buying_data/buying_history.csv`
2. `.env` の `RAW_BUYING_PATH` にフルパスを書く

生データは数百万行になることがあります。初回の集計と学習には数分かかることがあります。

## 4. 構築手順

以下、プロジェクトのルートで実行します。

### 4.1 ソースを置く

```bash
# Git の場合（リポジトリ URL は配布元に合わせて変更）
git clone <リポジトリURL>
cd <プロジェクトフォルダ>
```

学習データを別送されている場合は、ここで `data/real_store_daily.csv` を置きます。

### 4.2 Python 仮想環境と依存パッケージ

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```



### 4.3 環境変数（任意）

施策提案LLM を使う場合だけ必要です。無くても予測画面は動きます。

```bash
cp .env.example .env
```

`.env` を開き、使うキーだけ記入します。

```
LLM_PROVIDER=auto
GEMINI_API_KEY=
OPENAI_API_KEY=
```

- `auto` … Gemini キーがあれば Gemini、なければ OpenAI
- キーがどちらも空 … 施策チャットはルールベース（固定文の下書き）

生データの場所を固定したいときだけ:

```
RAW_BUYING_PATH=/path/to/buying_history.csv
```



### 4.4 API を起動する（ターミナル1）

**プロジェクトルート** で起動します。

```bash
source .venv/bin/activate
uvicorn api.main:app --reload --port 8000
```

初回は学習のため数十秒〜数分かかることがあります。成功すると次のようになります。

- `data/real_store_daily.csv` がある、または生データから自動変換できた → `GET http://127.0.0.1:8000/health` が `"status":"ok"`
- データがまだ無い → `"status":"need_data"` のまま起動する。予測画面は開くが、店舗一覧は空

確認:

```bash
curl http://127.0.0.1:8000/health
```

API の仕様一覧: [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)

### 4.5 Web を起動する

新しいターミナルを開き、次を実行します。

```bash
cd web
npm install
npm run dev
```

表示された URL（通常は [http://127.0.0.1:3000](http://127.0.0.1:3000) ）をブラウザで開きます。

フロントは既定で `http://127.0.0.1:8000` の API を呼びます。API のポートを変えた場合は、起動前に:

```bash
export NEXT_PUBLIC_API_URL=http://127.0.0.1:ポート番号
npm run dev
```



### 4.6 画面の確認

1. [http://127.0.0.1:3000](http://127.0.0.1:3000) を開く
2. 店舗が選べることを確認する
3. 粒度（日次／週次／月次）を選んで予測を実行する
4. 右側のチャットで施策文が出るか確認する（キー無しならルールベース）

「予測のしくみ」ページは API が止まっていても開けます。

## 5. データの扱い

予測モデルが読むのは **店舗×日に集計した表** だけです。生の購買伝票（`buying_history.csv`）をそのまま学習しません。

この集計表が `data/real_store_daily.csv` です。

### 起動時

API は次の順で動きます。**集計表があるかどうかが先**です。

1. `data/real_store_daily.csv` がある → それを学習する
2. 集計表が無い → 3.2.B の生購買を店舗×日に集計し、`data/real_store_daily.csv` を作ってから学習する



### データを更新するとき

**どちらか一方**です。生ファイルを置いたうえで `real_store_daily.csv` も自分で置き直す、という手順ではありません。


| 手元にあるもの                           | 手順                                                                                         |
| --------------------------------- | ------------------------------------------------------------------------------------------ |
| 集計表（`real_store_daily.csv`）だけ     | そのファイルを `data/` に上書きして **API を再起動**する。生購買は不要                                               |
| 生購買（`buying_history.csv`）から作り直したい | 古い `data/real_store_daily.csv` を**消して**から、生ファイルを 3.2.B の場所に置いて API を再起動する。無い集計表は起動時に作り直される |
