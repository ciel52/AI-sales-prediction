# 環境構築手順書（来店・売上予測デスク）

動作確認済みの目安: **Python 3.12** / **Node.js 22** / macOS。Windows でも同じ流れです（起動コマンドだけ末尾を参照）。

---

## 1. 完成イメージ

2つのプロセスを同時に動かします。


| 役割  | アドレス                                           | 中身                 |
| --- | ---------------------------------------------- | ------------------ |
| API | [http://127.0.0.1:8000](http://127.0.0.1:8000) | 学習・予測・データ取込・施策チャット |
| Web | [http://127.0.0.1:3000](http://127.0.0.1:3000) | 予測デスク画面            |


ブラウザで開くのは **[http://127.0.0.1:3000](http://127.0.0.1:3000)** です。画面上部に「予測デスク」「予測のしくみ」があります。

学習データがあれば店舗を選んで日次／週次／月次の予測ができます。LLM の API キーが無くても、数値予測とルールベースの施策文は動きます。

## 3. 配布物（ここが重要）

`git clone` しただけでは **動きません**。次の2点をセットで渡してください。

### 3.1 ソースコード

少なくとも次が入っていること。

```
api/          FastAPI
web/          Next.js
src/          予測・ETL・施策提案
requirements.txt
.env.example
```

GitHub 上の古いコミットには `api/` と `web/` が無いことがあります。渡す前に、上記フォルダがあるか確認してください。

検証用の `archive/` は社内構築には不要です。あっても害はありません。

### 3.2 学習データ（どちらか一方）

`data/*.csv` と `test_data/` は Git に入れていません（実データのため）。次の **A または B** を用意します。

**A. 集計済みパネル（推奨・すぐ起動できる）**

`data/real_store_daily.csv` をプロジェクトの `data/` に置く。

必要な列の例: `shop_id`, `date`, `receipts`, `net_sales`, `avg_spend` など。既存の検証用ファイルは約 640KB です。

**B. 生の購買履歴（サーバで自動変換）**

CSPM の購買履歴（TSV または CSV）。必要な列:

- `V_ACCOUNT_ID`
- `D_TRANSACTION_DT`
- `V_SHOP_ID`
- `C_SLIP_TYPE`
- `N_PURCHASED_AMOUNT`
- `N_DISCOUNT_AMOUNT`

ブラウザからのアップロードは使いません。配置場所は次のどれでも構いません。API 起動時に自動で店舗×日へ変換します。

1. `test_data/buying_data/buying_history.csv` に置く
2. `.env` の `RAW_BUYING_PATH` にフルパスを書く

生データは数百万行になることがあります。初回の集計と学習には数分かかることがあります。

将来は社内DBから同じパネル（または生購買）を自動取得する想定です。

## 4. 構築手順

以下、プロジェクトのルート（`README.md` があるフォルダ）で実行します。

### 4.1 ソースを置く

```bash
# Git の場合（リポジトリ URL は配布元に合わせて変更）
git clone <リポジトリURL>
cd <プロジェクトフォルダ>
```

zip の場合は展開して、その中に入ります。

学習データを別送されている場合は、ここで `data/real_store_daily.csv` を置きます。

```bash
mkdir -p data
# 受け取った CSV を data/real_store_daily.csv として配置
```



### 4.2 Python 仮想環境と依存パッケージ

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

`.venv` は Git に含めません。各 PC で一度だけ作ります。

### 4.3 環境変数（任意）

LLM を使う場合だけ必要です。無くても予測画面は動きます。

```bash
cp .env.example .env
```

`.env` を開き、使うキーだけ記入します。

```
LLM_PROVIDER=auto
GEMINI_API_KEY=
OPENAI_API_KEY=
```

- `auto` … Gemini キーがあれば Gemini、なければ OpenAI
- キーがどちらも空 … 施策チャットはルールベース（固定文の下書き）

`.env` は Git にコミットしないでください。

生データの場所を固定したいときだけ:

```
RAW_BUYING_PATH=/path/to/buying_history.csv
```



### 4.4 API を起動する（ターミナル1）

必ず **プロジェクトルート** で起動します。`web/` の中では動きません。

```bash
source .venv/bin/activate
uvicorn api.main:app --reload --port 8000
```

初回は学習のため数十秒〜数分かかることがあります。成功すると次のようになります。

- パネルがある、または生データから自動変換できた → `GET http://127.0.0.1:8000/health` が `"status":"ok"`
- データがまだ無い → `"status":"need_data"` のまま起動する。予測画面は開くが、店舗一覧は空

確認:

```bash
curl http://127.0.0.1:8000/health
```

API の仕様一覧: [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)

このターミナルは閉じないでください。

### 4.5 Web を起動する（ターミナル2）

新しいターミナルを開き、次を実行します。

```bash
cd web
npm install
npm run dev
```

表示された URL（通常は [http://127.0.0.1:3000](http://127.0.0.1:3000) ）をブラウザで開きます。

フロントは既定で `http://127.0.0.1:8000` の API を呼びます。API のポートを変えた場合は、起動前に:

```bash
export NEXT_PUBLIC_API_URL=http://127.0.0.1:8000
npm run dev
```



### 4.6 画面での確認

1. http://127.0.0.1:3000 を開く
2. 店舗が選べることを確認する（学習CSVが `data/` にあれば、取込操作は不要）
3. 粒度（日次／週次／月次）を選んで予測を実行する
4. 右側のチャットで施策文が出るか確認する（キー無しならルールベース）

「予測のしくみ」ページは API が止まっていても開けます。

## 5. データの扱い

予測モデルは **生伝票を直接学習しません**。店舗×日に集計した `data/real_store_daily.csv` だけを使います。

起動時の動き:

1. `data/real_store_daily.csv` があればそれを学習する
2. 無ければ、配置済みの生購買から自動で集計してから学習する
3. どちらも無ければ、API は起動したままになる（予測画面は表示されるが店舗は空）

再学習したいときは、パネルCSVを差し替えて API を再起動するか、`POST /data/ingest` を呼びます。画面からのファイルアップロードはありません。

`receipts` は売上伝票（`C_SLIP_TYPE=RCPT`）の件数で、購買来店の代理指標です。

## 6. よくある問題


| 症状                            | 確認すること                                                   |
| ----------------------------- | -------------------------------------------------------- |
| 画面に「学習データがまだありません」 | `data/real_store_daily.csv` があるか。API を再起動したか |
| 画面に API 接続エラー | ターミナル1で API が起動しているか。`curl http://127.0.0.1:8000/health` |
| `uvicorn: command not found` | `source .venv/bin/activate` してから起動しているか |
| 取込で「必要な列がありません」 | 3.2 の列名になっているか。Excel で開いて保存し直すと列名が変わることがある |
| 文字化け・読めない                     | UTF-8（BOM 付き可）または Shift_JIS（cp932）を試す。区切りはタブ／カンマ自動判定     |
| 店舗一覧が空                        | 集計後に `C_SLIP_TYPE=RCPT` の行があるか                           |
| チャットが英語や的外れ                   | `.env` のキーと `LLM_PROVIDER`。キー無しならルールベースになる               |
| `npm: command not found`      | Node.js が入っていない                                          |
| ポート 3000 / 8000 が使用中          | 他の開発サーバを止めるか、ポートを変える                                     |


API のポートを 8001 にする例:

```bash
uvicorn api.main:app --reload --port 8001
```

Web 側:

```bash
cd web
NEXT_PUBLIC_API_URL=http://127.0.0.1:8001 npm run dev
```

## 7. Windows の場合

コマンドプロンプトまたは PowerShell で、仮想環境の有効化だけ異なります。

```bat
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
uvicorn api.main:app --reload --port 8000
```

別ウィンドウ:

```bat
cd web
npm install
npm run dev
```

パスに日本語や空白があると失敗することがあります。可能なら短い英数字のフォルダに置いてください。

---



## 8. 止めるとき・やり直すとき

- 各ターミナルで `Ctrl+C`
- 依存関係を入れ直す: `pip install -r requirements.txt` / `cd web && npm install`
- 学習結果はファイルに保存していません。API を起動するたびに `data/real_store_daily.csv` から再学習します
- パネル CSV を差し替えたら、API を再起動してください
